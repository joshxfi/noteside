# AGENTS.md

Guidance for any coding agent working in this repository — the single, tool-agnostic source of truth for how Noteside is built. Keep it accurate as the architecture changes.

## What this is

Noteside — an offline, **performant, minimalist notes desktop app for everyone**: a Notion-like WYSIWYG block editor over plain markdown files, where mouse and keyboard are BOTH first-class (vim essentials, conventional shortcuts, and pointer-driven UX — pick any, mix freely), plus its marketing site. This is a deliberate repositioning away from the original "keyboard-first" identity (2026-08): every command must be reachable by mouse AND by keyboard. When adding UI, hold the parity rule in both directions: a new button gets a command-table entry (keyboard/palette path), a new command gets a visible pointer affordance — and pointer affordances must be CSS-driven where they can be (hover reveals never add per-row React state; the perf invariants below are not negotiable). Turborepo + pnpm monorepo:

- `apps/desktop` — Tauri 2 + React 19 + Vite + TypeScript (the app)
- `apps/landing` — Vite + React 19 + TypeScript + Tailwind v4 (the site)
- `apps/docs` — Fumadocs on React Router 8 (SPA, prerendered) — the documentation site at **docs.noteside.app** (`:3002` via `pnpm dev:docs`)
- `apps/brand` — Vite + React + Tailwind, the standalone **brand guide** (internal reference only; not deployed, not linked from the landing). Runs on `:3001` via `pnpm dev:brand`; has its own `logo.tsx` copy + `styles.css` (the brand CSS).

**Performance posture (measured — see `benches/perf.rs` + `src/perf.bench.ts`).** `fuzzy_files` is ~1ms even at 50k (nucleo; a score-only pass picks the top 200, then `indices()` runs only on the returned page — the match-heavy case is ~3.5ms @50k, 1.7× faster than single-pass; the no-match case pays a ~25% score-pass tax and stays ~1ms). `content_search` prefilters each note's **whole body** (SIMD regex / `contains`; built lazily once a scan outlives 128 notes so short scans don't pay the compile) before the per-line pass — a rare/no-match query (the old worst case) is ~0.5ms @1k, ~3ms @10k, **~15ms @50k** (was ~95ms); matching queries are 15–20% faster; no DB or index to build or sync. `scan_notebook` reads files across scoped threads and path-sorts the records (deterministic order for binary-search lookups) — ~8ms @1k, ~89ms @10k, one stat per file. The **watcher** applies targeted upserts/removes for unambiguous create/modify/remove events and full-rescans for everything else (renames and mixed/ambiguous batches); any read/scan failure preserves the current index for a later retry. `[profile.release]` is `opt-level = 3` + fat LTO. On the JS side: **typing never re-renders React beyond the editor's own status bar** (the session snapshot bails on no-change, `shouldRerenderOnTransaction` is false, and every NodeView is plain DOM); **markdown serialization never runs on the typing path** — `onChange` hands the session a THUNK over the immutable PM doc, so `manager.serialize` (~0.45ms @1k lines, ~5ms @10k) runs only when the 800ms autosave debounce (or an explicit save) materializes it, and `manager.parse` (~4ms @1k, ~300ms @10k — the price of opening a pathological note, see `perf.bench.ts`) runs once per open; the status bar's **word count is a delta, not a rescan** (`editor/word-count.ts` over the `editor/pm-doc.ts` adapters: each transaction step re-counts only its textblock-expanded ranges — exact, because a block boundary is whitespace so no word can straddle one — ~6µs per keystroke, flat in doc size; `word-count.test.ts` pins the invariant `total + delta === full rescan` with real PM transactions incl. a seeded fuzz); **cursor motion is cheap** (the active-block decoration reuses its set when the block is unchanged, and the vim caret is one decoration recomputed on selection changes only); the **sidebar virtualizes** above 100 notes (`@tanstack/react-virtual`; the plain list renders verbatim below) and rows are memoized (an autosave re-renders 1 row); the **first paint** neither parses the editor chunk (lazy, §editor; `check:editor-lazy` pins this in CI — the KaTeX chunk rides with it, never eager) nor waits on IPC (config + last-notebook load in parallel).

Lint/format are oxc, run from the repo root (not per-package, not through Turbo): `oxlint` (`.oxlintrc.json`, correctness=error/suspicious=warn, react+typescript+import plugins — the react plugin includes the React-Compiler-derived rules `react/refs`, `react/set-state-in-effect`, `react/exhaustive-effect-dependencies`, so a "latest value" ref is written from an effect, never during render, and prop→state syncing is derived at render instead; a closure that reads a ref at EVENT time but is created inside a render-time call gets a one-line `oxlint-disable-next-line react/refs` with the reason; `react/exhaustive-effect-dependencies` is OFF in `.oxlintrc.json` — it misreads `useRef` results as missing deps and flags every deliberate trigger effect like `[props.refocusToken]`) and `oxfmt` (`.oxfmtrc.json`; pinned exactly — still beta). The codebase is kept oxfmt-formatted, **including `styles.css`** (so it's no longer byte-identical to the design source — diff semantically, not line-for-line) — **except `src/test-vectors/round-trip/`**, byte-exact serializer fixtures excluded in both `.oxfmtrc.json` and the lefthook glob (a reformat like `*em*`→`_em_` silently breaks their identity tests). Tests: **Vitest** (`pnpm test`, node env — pure modules only, no DOM) covers `autosave.ts` (incl. in-flight durability barriers), `editing-session.ts`, `settings.ts` round-trip, `markdown.ts` (frontmatter + `scanTopBlocks`), `editor/markdown-io.ts`, **`editor/round-trip.test.ts` (the fidelity centerpiece — fixed-point + byte-identity over `test-vectors/round-trip/*.md`, built from the SAME `markdownExtensions()` the app mounts)**, `editor/goto.test.ts` (scanTopBlocks ↔ parser block-count agreement), `editor/word-count.ts` + `pm-doc.ts`, the vim machine + motions (`editor/vim/*.test.ts`), and the mock backend. ("No DOM" still allows real engine values: `@tiptap/pm` state/model and the headless `MarkdownManager` load fine in the node env, which is how the word-count, round-trip, and vim-motion tests drive real docs and transactions.) Also **cargo test** (`pnpm test:rust`) covers `commands`/`notebook`/`search`/`state`/`watcher`/`frecency` (`#[cfg(test)]` modules); **Playwright e2e** (`apps/desktop/e2e`, `pnpm e2e`) drives the web build + mock backend on :1420 in chromium AND webkit (≈ WebView2 / WKWebView parity) — it runs in CI, so UI changes (settings rows, picker markup, chords) must update the specs. `pnpm typecheck` + `pnpm lint` + `pnpm format:check` + build/lazy-chunk verification + all three test layers are the gates.

## Architecture: the parts that span files

**The editor is a Notion-like WYSIWYG block editor on Tiptap v3 / ProseMirror** (`apps/desktop/src/editor/`) — **markdown files stay the source of truth**: `editor.tsx` parses disk text at mount (through `@tiptap/markdown`'s `MarkdownManager`) and serializes back to markdown on save. The seams the app relies on: **(1) the onChange thunk** — every doc change hands the session `() => joinNote(io, manager.serialize(doc.toJSON()))` over the IMMUTABLE captured doc, so serialization runs at write time, never per keystroke; **(2) doc.eq dirtiness** — the editor compares against a saved-doc snapshot (advanced when `props.savedText` matches what the last thunk produced), exact and synchronous, retracting on undo-to-saved; **(3) the remount key** — `key={session.editorKey + ":" + vimSuffix}` (editorKey deliberately excludes `activeId` so rename-on-save repoints without a cursor jump); chords/escMap/tabWidth reconfigure live through refs, never a remount. `extensions.ts` is the one extension list: `markdownExtensions()` (the schema-bearing set — StarterKit+GFM, tables, task lists, KaTeX math, images, callouts, the raw-HTML passthrough — the EXACT config `round-trip.test.ts` pins) plus the editor-behavior layer (lowlight code blocks, active-block highlight, find, slash menu, hover grip, link-click, chords, Tab, vim). **The editor chunk is lazy**: `app.tsx` has NO static value import from `editor/` — `Editor` is `React.lazy` over a module-scope `import()` (fetch kicks immediately; the ~600KB Tiptap+PM parse stays off the first-paint path). Adding a value import from `app.tsx` (or anything eager) into `editor/*` silently re-eagers the chunk — check `dist/index.html` modulepreloads if you touch imports. The `advancedChunks` groups in `vite.config.ts` (Rolldown's native chunking API under `build.rolldownOptions` — Vite 8 bundles with Rolldown/Oxc, not Rollup/esbuild) guard this from the other side, and their ORDER is load-bearing: groups match in sequence and each pulls its matched modules' static dependencies along (`includeDependenciesRecursively`), so `react` is claimed BEFORE `editor` — otherwise `@tiptap/react`'s dependency on React drags React into the editor chunk and the entry imports that chunk statically, re-eagering the whole editor (exactly what the old function-form `manualChunks` silently did under Rolldown). Vite's preload helper is pinned to its own tiny chunk (it would otherwise be hoisted INTO the editor chunk and re-eager everything), **KaTeX gets its own cache-isolated chunk** (statically imported by math, so it loads WITH the editor chunk but never at first paint), and per-language highlight.js grammars stay separate lazy chunks (`code-block.ts` dynamic-imports from an allowlist and nudges a content-neutral `setNodeMarkup` refresh when one lands — `doc.eq` still holds, so a grammar load can never dirty the buffer). `scripts/check-editor-lazy.mjs` pins all three (editor + katex not eager, ≥1 lang chunk emitted).

**Every rich construct is a REAL block node, and the round-trip is the contract.** Serialization is canonical (ATX headings, `-` bullets, 2-space indent — pinned in `extensions.ts`, independent of `cfg.tabWidth` so settings never churn disk) and save-gated: opening a note never writes; the one-time reformat rides the first real edit, and `serialize(parse(x))` is a FIXED POINT for every vector after that (`round-trip.test.ts`). Fidelity fixes that live here and are easy to lose: **table cells escape literal pipes on serialize** (`table.ts` wraps the stock renderer — without it a `\|` cell corrupts on reparse); **raw HTML blocks survive verbatim** as opaque source chips (`html-passthrough.ts` claims marked's block `html` tokens ahead of the entity-escaping fallback; inline HTML can't be intercepted — a pinned, documented lossy case); **callouts are GFM alerts** (`> [!NOTE]` blockquotes, `callout.ts` — its handler also renders PLAIN blockquotes because the token registry doubles as the renderer lookup); **images keep their written src verbatim** (display URL resolves separately through the Tauri asset protocol against the notebook root — `image.ts`; the protocol's STATIC scope is empty and `open_notebook` grants each opened folder at runtime via `asset_protocol_scope()`, least-privilege design pinned by `tauri-capabilities.test.ts`). CRLF and the trailing newline are detected/reapplied by `editor/markdown-io.ts` so Rust's surgical rewrites and the watcher's disk-verified echo suppression stay coherent. Grep hits navigate by SOURCE LINE: `markdown.ts scanTopBlocks` segments the body the way the parser tokenizes (agreement pinned in `goto.test.ts`, clamp fallback in `editor/goto.ts`).

**Frontmatter never reaches the editor at all.** `editor/markdown-io.ts` splits the leading `---` block off VERBATIM before parse (`scanFrontmatter` mirrors Rust `split_frontmatter` exactly: bare `---` on line 0; closed by the first later `---` after trailing whitespace; unclosed ⇒ not frontmatter) and re-attaches it byte-identically on serialize — so everything `parse_meta` reads (`title:`/`tags:`/`pinned:`) survives every save untouched, and a pinned note simply opens on its title with no caret-parking dance. Hidden, not summarized: `pinned:` is bookkeeping the app writes for itself and the sidebar's pin icon is already the user-facing signal — don't reintroduce a chip/properties row for it. When Rust rewrites the YAML behind the editor's back (`set_pinned`/`retitle_note`), the existing flush+pause+reopen machinery remounts the editor, whose mount re-splits the fresh disk text — `pin.spec.ts` pins that an autosave after pinning cannot write the frontmatter away (the held block is re-attached by the serialize thunk).

**`editor/commands.ts` is the single command table.** Every command (id, title, chord, ex-names, leader key, `editor`-action) lives here; the vim ex bar, the `<Space>` which-key palette, the always-on `Mod-` chord layer, the searchable command palette (`CommandSearch`), the `Mod-/` cheatsheet, and button tooltips all DERIVE from it — add or rebind a command in one place. The file is 100% dependency-free: chords are matched by `eventChord(e)` against the memoized `editorChordMap` (editor scope, includes editor-action commands) or `globalChordMap` (document-level fallback, `use-global-chords.ts`, command-kind only, gated on overlay React state) — flag-based matching, so shifted punctuation works on every platform with **no glyph aliases** (Playwright specs may press `Shift+Equal` again; the CM-era "press the glyph" rule is dead). The editor-side layer is `editor/chords.ts` (a priority-2000 plugin reading overrides through a ref — a rebind applies live with no remount and no focus theft from the open cheatsheet). **The leader palette has two first-class paths**: `<Space>` in vim normal mode and the `Mod-l` chord (rebindable; listed in palette + cheatsheet). In-note find is `prosemirror-search` behind `editor/find.ts` + `find-bar.tsx` — ONE engine for Mod-f, F3/Shift-F3, vim's `/`, `n/N`, `*`/`#`, and `:noh`; Esc closes the bar but highlights persist (hlsearch parity), the ✕ clears. **Tab keeps the issue-#23 semantics** (`extensions.ts` tabKey): in a TABLE it moves to the next cell and grows a fresh row past the last one (this clause MUST come first or the fallbacks shadow it — the bug where Tab typed spaces into cells), in a list it nests/unnests the item, otherwise it inserts `cfg.tabWidth` spaces AT THE CARET via a raw `tr.insertText` (never `insertContent` — the markdown-aware override eats whitespace-only strings); vim normal/visual swallow Tab so focus can't escape the editor. **Table structure ops** (`tableAddRow`/`tableDelRow`/`tableAddCol`/`tableDelCol`) are ordinary command-table entries — palette-searchable and ex-named (`:addrow`/`:delcol`/…); the pointer path is `editor/table-toolbar.ts`, a floating bar over the caret's table whose buttons dispatch those same commands. The palette reaches editor-action commands through the **`onRegisterDispatch` prop** (app.tsx holds the open editor's dispatch in a ref): explicit prop wiring, never a module-singleton registry — the editor is a dynamic chunk, and a shared module splits into two instances the moment dev HMR timestamps one importer's URL. The registration retires by function IDENTITY (`alive: false`) because `useEditor` DEFERS destruction: on a note switch the outgoing editor's teardown lands AFTER the incoming one registered, and a naive `null` would blank the live dispatch. Non-vim users are first-class; `bind <chord> <command-id>` lines in `~/.notesiderc` remap chords. User chords must include Cmd/Ctrl/Alt or use an F-key; the shared `shortcut.ts` validator is enforced during boot migration, config parsing/serialization, cheatsheet recording, and both dispatch boundaries so a stale/bad binding can never hijack ordinary typing, Tab, Enter, or cursor movement. The `Mod-/` cheatsheet (`components/cheatsheet.tsx`) is itself the **in-app keymap editor**, and it's **search-first** — an auto-focused input filters the grouped list by title/ex/group (`list-nav.subseq`, the same fuzzy filter the finder/command-palette/theme-picker/slash-menu use), `↑↓` (or `Ctrl-n/p`) select, `Enter` records a chord (`Backspace`=unbind, `Esc`=cancel inside recording), an empty-query `Backspace` unbinds the selected row, and reset lives on the per-row `⟲` button + the footer's "Reset all keys". Clash detection via `chordConflict` (commands.ts); edits write `cfg.chords` (→ `bind` lines).

**Vim is a hand-built subset (`editor/vim/`), not an emulation layer — navigation AND the everyday edit grammar are the bar.** `machine.ts` is a PURE key state machine (keys in, intents out — no PM, no DOM, no timers; exhaustively node-tested), `exec.ts` is STATE-pure (`EditorState` + intent → `Transaction`; `exec.test.ts` drives real keys → intents → transactions against the app schema, so every edit below is node-tested), `motions.ts` is the position math (line units, word/seek/bracket motions, text objects, the cursor clamp), and `index.ts` (a priority-1500 extension, below chords, above content keymaps) owns the glue: mode state, the vim-side visual selection, the block-caret decoration, coords-based j/k with a sticky goal column, undo grouping, `.` recording, scrolling, `o`/`O`, and the app hooks. IN: normal / insert / visual (charwise `v`, linewise `V`, `o` swaps ends; a mouse drag or select-all in normal mode IS visual mode), motions `h j k l w b e 0 ^ $ gg G { } %` with counts, `f t F T ; ,`, `N G`, Enter/Backspace as `j`/`h`, `Ctrl-d/u/f/b` (macOS only — elsewhere Ctrl is the chord modifier), `zz zt zb`; operators `d c y > <` with ANY motion or text object (counts multiply: `2d3w`), doubled for linewise (`dd cc yy >> <<`), plus `D C S Y s x X`; text objects `iw aw ip` and `i"/a"` `i'` `` i` `` `i( i[ i{ i<` (`b`/`B` aliases, either bracket); `p P r ~ J`, `.` over the last change (insert text captured through Esc; a multi-line insert says it can't repeat), one unnamed register, `u`/`Ctrl-r` → the editor's history, `/ n N * #` through the shared find engine, `:` ex bar (`ex-bar.tsx` exact-matches every command-table ex name + `:N` + `:noh`), `<Space>` leader, `gx` follow, escMap (insert-then-remove within 350ms), `Ctrl-[` = Esc. OUT (deliberate): named registers, macros, marks, replace mode `R`, blockwise visual, `gu/gU`, `:s` — anything needing recording or register plumbing. Rules a vim user feels, all pinned in tests: **the normal-mode cursor sits ON a character** (`clampNormalPos`, applied in `appendTransaction` to every collapsed selection while in normal mode — `$` parks on the last char, `x` there steps back, arrows/clicks/undo all obey), `h`/`l` never leave the line and **charwise operators never cross a block boundary** (`dw` on the last word stops at the line end), `cw` on a non-blank is `ce` (vim's documented quirk), seeks are inclusive forward / exclusive backward, `dd` uses `deleteRange` so the sole item of a list, the last row of a table, or the last paragraph of a quote takes the empty wrapper along, `J` joins only siblings (paragraphs sharing a parent, or two single-paragraph list items), `>>`/`<<` are PM's own `sinkListItem`/`liftListItem` grafted onto the state (code lines indent by `tabWidth`; a paragraph is a quiet no-op — markdown has no paragraph indent), and **an insert session is one undo step**: vim mode raises `newGroupDelay` to 30s and the layer `closeHistory`s the change tr and dispatches a sealing no-op after every normal-mode edit (a `c`-op keeps its group open so `cwfoo<Esc>u` restores the word). The visual selection is vim-side (`vsel` cursor positions, the char under the head included) and the PM selection is DERIVED from it (`visualSelection`) — never read the PM head back as the vim cursor. **The line-unit rule** makes linewise commands uniform: `dd` on a heading deletes the heading, in a list the ITEM, in a table the ROW (`o`/`O` there add a row), in a code block the current SOURCE LINE, inside a blockquote/callout the paragraph. The status bar echoes the pending count/operator (`onPending` → `.av-showcmd`, vim's showcmd). In insert mode the vim layer watches ONLY Esc/Ctrl-[ + escMap — typing, input rules, and the slash menu behave exactly as for non-vim users. Two hard-won WebKit rules encoded in `index.ts`: `o`/`O` route through the SAME split commands a real Enter uses plus a next-task caret reassert (inserting a node and selecting into it inside one keydown gets bounced) — and the mode flips to insert BEFORE the split so the clamp can't fight the intermediate placements — and after every vim dispatch the DOM selection is force-synced to state (`syncDomSelection`) so a stale queued `selectionchange` can't teleport the caret.

**Do NOT wrap the desktop app in `<React.StrictMode>`.** `apps/desktop/src/main.tsx` deliberately omits it. StrictMode's dev double-invoke of effects would double-create the Tiptap editor (`useEditor` with `immediatelyRender: false` builds it in an effect) and double-fire mount work. Related hard rule in `editor.tsx`: the editor is created in an effect, focus is dispatched selection-first-then-DOM-focus (never `commands.focus()` at create — its mid-command `view.focus()` makes WebKit fire a reentrant selectionchange that stales the transaction: "Applying a mismatched transaction"), and Tiptap's own `autofocus` option stays OFF. The landing app _does_ use StrictMode (no such pattern).

**The per-buffer state machine lives in `editing-session.ts`** — a framework-free `createEditingSession` store (working/saved/dirty, autosave, open/save/quit, config-as-a-buffer-kind, external reconcile, and the editor remount `key`), consumed via `use-editing-session.ts` (`useSyncExternalStore`). It imports no React, so the whole loop is node-testable (`editing-session.test.ts`). `app.tsx` drives the session and owns the sidebar list, config _semantics_ (`onConfigApply`), and panels — it **no longer holds the working/saved maps**. Autosaves and explicit save+rename flows share one serialized operation tail: `flush()` awaits queued, timer-fired, and in-flight writes, so note switches, duplication, notebook switches, and native close are real durability barriers. Delete pauses autosave synchronously (capturing edits that arrive during the IPC); success discards them with navigation, while failure resumes the latest request. The Editor is remounted via its `key` (`session.editorKey` + a vim suffix only — chords/escMap/tabWidth reconfigure live via refs, see §config) so cursor position resets cleanly. **`editorKey` deliberately excludes `activeId`** (it keys on `gotoLine:reloadNonce:navSeq`, and `navSeq` bumps on every `open`) — so **rename-on-save** can migrate the buffer's id in place without remounting (no cursor jump). On an **explicit save** (`:w`/Mod-s, never autosave — avoids churn while the title is being typed), and only when the write **landed** (`persistNote` resolves with the saved meta — a failed save must not rename from stale disk content), the session **pre-checks the meta's title client-side** (`stemMatchesSlug`/`slugifyTitle` from links.ts — the same rules the backends apply) and skips the rename IPC when the filename already matches (the common `:w` costs one round-trip, not two); otherwise it calls `backend.renameNote(id)`; if the file's slug no longer matches its title the backend renames it **within the note's own directory** (nested notes are never hoisted to the root) and returns a new meta. The session then **re-pins any queued autosave** to the new id (`autosaver.repin` — a keystroke during the rename IPC would otherwise recreate the old file), migrates `lastNoteId`, migrates `activeId`/`noteTitle` **only if the buffer is still active**, and fires `onNoteRenamed(oldId, meta)` (App swaps that sidebar row).

**The `~/.notesiderc` config buffer is a synthetic note — edited in a plain textarea.** `activeId === "config"` renders `editor/plain-editor.tsx` (the block editor would markdown-mangle a dotfile) inside the same `.av-editor` shell; Mod-s (or the [+] chip) runs `parseConfig` (settings.ts) and applies it — same `unrecognizedDirectives` error toasts, same "kept as written" section. `settings.ts` round-trips `Config ⇄ text` via `serializeConfig`/`parseConfig`; the in-app `SettingsPanel` and the config buffer are two editors over the same `Config`. Config changes are applied by writing CSS custom properties (`--editor-font`, `--editor-size`, `--ui-scale`, the theme palette, etc.) onto `document.documentElement` in an effect in `app.tsx` — **split from persistence**: the var-writing effect keys on the visual fields only, and `backend.setConfig` is debounced ~300ms (flushed on `pagehide`/unmount) so held settings-steppers don't do an IPC/localStorage write per repeat. The applied theme is also mirrored to `localStorage["noteside:boot-theme"]` (id + mode + inline vars): the `index.html` head script paints it and `bootConfig()` seeds the initial `cfg` from it, so a dark/base16 user never sees a light first frame while the config store loads (the store remains the source of truth). Beyond the obvious fields, `Config` carries `theme` (a **theme id string** — see the Themes paragraph below) and `uiScale` (a 90–130% **UI-chrome** scale — the editor is immune since it sizes from `--editor-size`). **Accepted-but-inert keys** (block-editor consequence): `live-preview` (no source/preview split) and `relative-numbers` (no gutter) still parse in every legacy spelling — never an error toast — but are no longer serialized or shown in Settings; vim `:map` keymap lines round-trip VERBATIM but the vim subset doesn't apply them, and the config-apply toast says so honestly. **Only a vim-mode change remounts the editor**; chords/escMap/tabWidth reconfigure the live view through refs — a remount there would lose cursor + undo history and reseed from open-time text. `font-size` floors at 16.

**The config buffer is lossless, and it is NOT a file.** Nothing reads or writes a real `~/.notesiderc` — the name is a label on a synthetic buffer over the `Config` object. Because `serializeConfig` regenerates that text from scratch, every line `parseConfig` didn't recognize used to disappear on the next open while the toast still said "config applied" (issue #24). Now: unmatched lines land in `Config.extraLines` and are re-emitted verbatim under a "kept as written" header, and `unrecognizedDirectives()` drives an error toast naming what did nothing. The parser distinguishes **our** boilerplate comments from the user's by comparing against the `C` constants serializeConfig writes — one source, so they can't drift and a reopen can't duplicate a header (`settings.test.ts` pins idempotency across repeated round-trips). Anything newly taught to the parser automatically stops being kept as an extra. Deliberate exception: an unsafe `bind` chord is still consumed and dropped, since `isSafeChord` rejection is a guard, not a parse failure.

**Search lives behind the `backend/` seam.** The `Backend` interface (`src/backend/types.ts`) exposes `searchFiles(query) → FileHit[]` and `searchContent(query, mode) → ContentHit[]`. The Tauri adapter (`backend/tauri.ts`) `invoke()`s the Rust commands `search_files`/`search_content` (`src-tauri/src/search.rs`: nucleo `fuzzy_files` for path + title matching (separate `positions`/`titlePositions` highlight ranges), a `content_search` scan for plain/regex/fuzzy — every highlight offset crosses the IPC as **UTF-16 code units**, the encoding JS slices strings by, converted at the producer in search.rs), and the in-memory `mock.ts` backs browser dev + the landing demo. `Finder` only talks to the `Backend` interface, so it's identical in both modes — and search stays fully in-memory (no database). **Frecency ranks the finder** (`src-tauri/src/frecency.rs` + the same math in mock.ts): `EditingSession.open()` fire-and-forgets `backend.recordOpen(id)` on every USER navigation (never on watcher reloads), which bumps a 7-day-half-life decayed score persisted per notebook in `frecency.json` under the app data dir (pruned to 500). The empty finder query sorts recents by (pinned, effective frecency, updated) — never-opened notes keep the old order — and non-empty queries get a bounded ≤+15% score nudge so text relevance stays dominant; entries follow renames and drop on delete. An empty frecency map is output-identical to pre-frecency ranking (regression-pinned in the Rust tests).

**Notebook switching is sequential (one open at a time), not tabs.** The Rust `open_notebook` command is re-entrant — `NotebookState::load` swaps root + index + frecency in one lock and the watcher is _replaced_ (`AppState.watcher`), so switching is just calling it again (no core Rust change was needed for the feature). The recents list is **TS-only**: `Backend.listNotebooks/rememberNotebook/removeRecentNotebook` (`NotebookRef {path, name, lastOpened}`) persist an MRU array under the `notebooks` store key (`tauri.ts`; migrated from the legacy single `lastNotebook` on first read, front = most recent), and the mock (`mock.ts`) mirrors it with a per-notebook `{recs, frecency}` map + a `current` pointer + an explicit `mru` array (a second `/demo-journal` notebook is seeded so the switcher is exercisable in browser dev / the landing demo / e2e). The switcher (`components/notebook-switcher.tsx`, `:notebook`/`Mod-o`/titlebar folder button) reuses the finder chrome; the initial selection lands on the most-recent OTHER notebook (alt-tab). App's `switchNotebook` **awaits `session.flush()` before** `openNotebook` swaps the index — the outgoing buffer's queued autosave must land in the OLD notebook first (`session.flush()` returns the promise for this). Two ways to add a notebook: **"New notebook…"** (an in-overlay create form — a name + a changeable parent location — that calls the Rust `create_notebook` command to `create_dir` a sanitized child folder, then opens it, empty) or **"Open folder…"** (the OS directory dialog). Both route through `switchNotebook`, so the outgoing buffer flushes either way.

**Folders organize notes into REAL subdirectories of the notebook** — flat collapsible groups in the sidebar (root notes first with no header, then one section per directory; `work/projects` is ONE group labeled with its full relative path, never a tree). symlink probe walking to the nearest EXISTING ancestor). **Folder names are keyed by their ON-DISK spelling**: `create_folder`/`create_note`/`move_note` resolve the destination through `notebook::disk_rel_dir` (canonicalize root + dir, strip) AFTER `create_dir_all`, so on a case-insensitive volume (macOS/Windows) typing `work` where `Work` exists yields `Work` — never a phantom second group, and `move_note`'s same-dir no-op compares those resolved rels (a string compare "moved" a note onto itself: the self hard-link collided and the note came back `-2`'d). `rename_folder`'s case-only exception is decided by IDENTITY (`canonicalize(new) == canonicalize(old)`), never by comparing spellings — on ext4 `Work`→`work` with both present would otherwise let POSIX rename replace an empty target; ## Releases

**Releases are deliberate and batched — a manual GitHub Action, not per-push.** Run the **Release** workflow (`.github/workflows/release.yml`, `workflow_dispatch`; set the `dry_run` input to preview the version/notes) when you want to ship the desktop app; the landing/docs keep their own continuous Vercel cadence, so the two are decoupled. The pipeline: **semantic-release** (`.releaserc.json`, conventionalcommits preset) computes the version, writes `CHANGELOG.md`, bumps the version files, and tags; the workflow creates a **draft** GitHub Release; a 4-target `tauri-action` matrix (macOS arm64/x64, `ubuntu-22.04` + `libwebkit2gtk-4.1-dev`…, windows) attaches binaries; and a final job publishes only after every target succeeds. The CI gate (`.github/workflows/ci.yml`) runs typecheck/lint/format/test/build/lazy-chunk verification + Rust fmt/clippy/test + Playwright on PRs and pushes to main.

The version is **derived from conventional commits** (`feat`→minor, `fix`/`perf`/`polish`/`refactor`→patch, `feat!`/`BREAKING CHANGE`→major), so commit hygiene is load-bearing. `node scripts/bump-version.mjs <version>` is the single sync point — it regex-patches the `version` in **8 files**: `apps/desktop/src-tauri/tauri.conf.json` (the binary's source of truth), `Cargo.toml`, the `noteside` entry in `Cargo.lock`, and the root + 4 app `package.json`s. These checked-in versions are synchronized release state; **don't hand-bump them**. Keep evergreen prose version-agnostic and point download CTAs at `…/releases/latest`. Builds are currently **unsigned** (one-time Gatekeeper/SmartScreen prompt) with no auto-updater — but the app **checks GitHub for a newer release** (`check-update.ts` → `api.github.com/.../releases/latest`, `isNewer` compare) and only ever surfaces a badge + the About row's download link, never installs. Draft releases are excluded, so a partially failed native matrix is never advertised. The check runs **on launch when the `auto-update` setting is on** (default; `Config.autoUpdateCheck`, a Settings switch) AND `isTauri()` (the web/demo never phones home, so e2e stays offline), throttled to **once/24h** via a `noteside:update` localStorage `{ts, latest}` cache (`dueForCheck`; client-only machine state, not the config file). The result lives in `app.tsx` (not SettingsPanel) so the boot check drives the Settings-button `.av-update-dot` with Settings closed; on a cache restore `isNewer(latest, version)` is re-evaluated so the badge self-clears once the user updates. The About row's manual "Check for updates" button forces an on-demand re-check through the same App state. Setup gotcha: the repo's _Settings → Actions → Workflow permissions_ must be **read+write**, or semantic-release can't push the tag/commit/draft release.

## Conventions & gotchas

- **TypeScript is strict** with `noUnusedLocals`, `noUnusedParameters`, and `verbatimModuleSyntax` (from `tsconfig.base.json`). Use `import type { … }` for type-only imports or the build breaks. **TypeScript is 7.x — the native (Go) compiler**; the `typescript` package's `tsc` IS the native binary (platform packages under `@typescript/typescript-*`), and `tsc --noEmit` is ~10× faster. Two TS ≥6 rules bite here: **`types` defaults to `[]`** (no automatic `@types/*` inclusion), so browser code never sees Node globals — the one node-env test that reads the repo (`release-workflow.test.ts`) declares `/// <reference types="node" />` for itself, and the `tsconfig.node.json` projects (Vite configs) list `"types": ["node"]` only where they use `process`; and the removed options (`baseUrl`, `outFile`, `target: es5`, `moduleResolution: node10`/`classic`, AMD/UMD/System `module`) are simply never used. `@types/node` tracks the runtime line (`^24`, the `.nvmrc` Node), not the newest major.
- **Source files are kebab-case** (`settings-panel.tsx`, `editing-session.ts`, `use-global-chords.ts`, `ex-commands.ts`) — never CamelCase. Exported component/identifier names stay PascalCase (`export function SettingsPanel`); only the _filename_ is kebab. `apps/docs` keeps React Router's own lowercase route-file convention. The macOS filesystem is case-insensitive, so a stale wrong-case import resolves locally but breaks the Linux CI build — rename with a two-step `git mv` and fix every import path.
- **The mock backend is an in-memory seed** (`src/data.ts`, used in browser dev / the landing demo); the real Tauri backend persists to Markdown files. Notebook scanning, no-clobber atomic file operations, and the watcher live in `src-tauri/src` (`notebook.rs`/`commands.rs`/`watcher.rs`); search stays fully in-memory (no database). The notebook index is **`Arc<Vec<Arc<NoteRecord>>>`** (`state.rs`): searches snapshot the outer Arc and run outside the lock; a mutation racing a live snapshot copies N pointers and rebuilds only the touched record — never the note bodies. The vector is **path-sorted everywhere** (scan sorts, `upsert_sorted` inserts at the binary-search insertion point) and every by-path lookup goes through `state::find_record` — keep both invariants together or lookups silently miss. Every async filesystem command captures `(canonical root, generation)` and verifies it before mutating state; latest-request tokens prevent out-of-order notebook scans from winning. Record mutations advance `revision`, so the watcher retries a refresh that raced a newer operation and uses a rare locked fallback rather than installing a stale scan. Echo suppression is **per relative path** (renames arm old+new) and **disk-verified**: a suppressed batch is ignored only after each path's disk mtime (or absence) still matches what our own write recorded — an external write landing inside the window refreshes instead of being swallowed, and a mixed own+external batch always refreshes. Because the index can still lag disk briefly, the body-REWRITING commands (`retitle_note`/`set_note_pinned`/`duplicate_note`) read the note fresh from disk; `rename_note` alone stays index-first (it moves the inode, never writes body bytes). `scan_notebook` is fallible and never installs a partial index. New notes publish complete temp inodes without clobbering a collision (`atomic_create_unique`); renames use `rename_unique`; retitles publish the new body before removing the old path (`retitle_unique`). `safe_note_path` canonicalizes the target/parent to reject symlink escapes. For external events the watcher first tries a **targeted update** (`watcher.rs::classify_events`/`targeted_updates` → `state::apply_external`); ambiguous batches rescan, while any read/scan error preserves the current index.
- **The desktop app bundles fonts locally** (`apps/desktop/src/fonts.ts`) so it runs **fully offline** — no Google Fonts request on launch. It does NOT import the `@fontsource/*` CSS (which ships every face in woff2 **and** woff — ~1.75MB of assets): fonts.ts imports the **woff2 files directly** (all subsets each family ships — latin/latin-ext plus cyrillic/greek/vietnamese/symbols2 where they exist; Newsreader/Spectral serif, IBM Plex/JetBrains/**Geist** mono) and injects self-authored `@font-face` rules (family/weight/style/`unicode-range` copied verbatim from the fontsource CSS) at module eval — zero `.woff`, glyph coverage identical to @fontsource. Two CSS font vars: `--serif` (Newsreader; editor default + palette) and `--mono` (**Geist Mono**, fixed — the whole interface, sidebar note titles included). **There is no interface-font setting** — only the editor font is user-selectable (`EDITOR_FONTS`; `cfg.editorFont`); `--mono` is a static var in styles.css, never written from config. Vite inlines any subset woff2 under 4KB as a base64 data URI instead of emitting a separate asset — expected, and harmless for an offline app (small Geist Mono subsets land this way). Adding a weight/style = add its subset woff2 imports + `face()` lines there. The **landing + docs** are websites, so they load Newsreader + IBM Plex Mono from Google Fonts (`index.html` / `root.tsx`); the brand guide too. CSS stacks fall back to system serif/mono everywhere.
- **UI icons are `lucide-react`** (in `app.tsx`), not hand-drawn SVGs — import each icon by name so the bundle tree-shakes to only what's used (bundled locally, no CDN, offline-safe). Render at `size={15}` to match the design: lucide's default `strokeWidth={2}` on its 24-grid renders ~1.25px at 15px, i.e. the old hand-tuned 1.3px weight. `color` inherits via `currentColor`, so the load-bearing classes (`.av-cfg-glyph`, `.ctx-glyph`, `.av-iconbtn svg`) still theme them — pass `className` through and keep decorative icons `aria-hidden` (the button carries the label). Not to be confused with the `tauri icon` CLI (§Commands), which generates the **app bundle** icon from `scripts/mark.html`.
- **Tauri Rust is a single crate** at `apps/desktop/src-tauri` (no root cargo workspace). Turbo does not cache the Rust build — `desktop#build` is the _web_ bundle; `tauri build` is separate. Window-control permissions and `data-tauri-drag-region` are authorized in `src-tauri/capabilities/default.json` (window label `main`). **A JS `onCloseRequested` listener requires `core:window:allow-destroy` there**: registering it makes Tauri core intercept the native close and trust the JS wrapper to `destroy()` the window — without the grant, the invoke is silently denied and the X button does nothing (the v1.3.0 bug; pinned by `tauri-capabilities.test.ts`). No automated layer exercises the native close path (e2e drives the web build) — manually click X after touching window-lifecycle code. The **sidebar note row's right-click menu is a native OS menu in Tauri** (`native-menu.ts` → one lazily-created reusable `@tauri-apps/api/menu` `Menu`, `isTauri()`-gated; items Open · Pin/Unpin · Reveal · Duplicate · Rename · ─ · Delete); app teardown calls `close()` so native resources do not accumulate. The Pin row is the one item whose label depends on the clicked note, so it's built as a retained `MenuItem` and `setText`-retargeted per popup rather than rebuilding (and leaking) the menu — `core:menu:default` already covers `allow-new`/`allow-set-text`. It needs `core:menu:default` + `opener:allow-reveal-item-in-dir` in the capabilities file (both pinned by `tauri-capabilities.test.ts`). **The web/landing demo gets the themed in-app menu instead** (`components/context-menu.tsx`, same items minus Reveal, dispatching the SAME handlers; also fed by each row's hover-revealed ⋯ kebab) — `context-menu.spec.ts` e2e-covers that path, but the NATIVE popup still isn't e2e-testable (e2e drives the web build), so **manually verify it in `pnpm dev:desktop`**. **Every menu item is backed by a real command** so it's keyboard-reachable AND e2e-covered without the native menu: Duplicate/Rename/Reveal/Pin are commands in `commands.ts` (`:dup`/`:rename`/`:reveal`/`:pin`+`:unpin`, palette), and Delete routes through the confirm modal. So the menu is a thin dispatcher — `app.tsx`'s `duplicateActive`/`renameActive`/`revealActive`/`pinActive`/`deleteActive` and the menu's per-note actions call the SAME handlers. The file ops live in Rust: `duplicate_note` (copy + retitle "X copy" in the source's own dir), `retitle_note` (publish the retitled body at a collision-safe path, then remove the old file), `set_note_pinned`, and `reveal_note` (opener plugin); the mock mirrors each. **Delete uses an in-app confirm modal** (`components/confirm-dialog.tsx`) and **Rename an input modal** (`components/prompt-dialog.tsx`), both themed like the Settings scrim (Esc cancels / Enter confirms), reachable via `requestDelete`/`requestRename`. Renaming, duplicating, or pinning the OPEN buffer flushes pending edits first.

**Pinning is frontmatter, so it is a body rewrite.** `pinned: true` in a note's frontmatter floats it above the `updated` sort in the sidebar, in `list_notes`, and in the finder's empty-query recents (it was parsed and sorted on long before anything could set it). `notebook::set_pinned` writes the key, opening a `---` block when the note has none; **unpinning removes the key and any block it emptied**, so pin→unpin is byte-identical to the original and a user who never pins never grows frontmatter (round-trip-pinned in `notebook.rs` tests and mirrored by `mock.ts`'s exported `setPinnedBody`, whose test file repeats the same cases). Pinning never changes the title: the block set_pinned writes carries no `title:`, so `parse_meta` still falls through to the same heading — the mock deliberately carries the old title over instead of re-deriving. Because it rewrites the file, `App.setNotePinned` **flushes the buffer, pauses autosave across the IPC (delete's machinery — a keystroke landing mid-round-trip would otherwise queue pre-pin text that lands after the reopen and unpins the file), and then reopens it** (as rename does) when the pinned note is the open one; skipping the reopen would leave the buffer holding pre-pin text, and the next autosave would silently write the pin away (`e2e/pin.spec.ts` pins that regression). Setting the state a note is already in short-circuits on both sides — Rust skips the write (identical bytes would still bump mtime, which IS the sidebar's sort key, so a redundant `:unpin` would jump the note to the top of "recently updated") and App skips the flush+reopen (a remount would throw the caret to the top for nothing). **`:pin`/`:unpin` are two commands, not one toggle with two ex-names** — sharing a toggling handler made `:unpin` PIN an unpinned note; `needsPinned` on the command table keeps the palette showing only whichever applies.

- **Toolchain: Node 24 + pnpm 11 + Vite 8** (`.nvmrc`, `packageManager` in root `package.json`). Vite 8 bundles with **Rolldown + Oxc** (esbuild/Rollup are gone from the build path; `build.rollupOptions` is the deprecated alias of `build.rolldownOptions`, and the object form of `manualChunks` no longer exists — see the `advancedChunks` note in §editor), `@vitejs/plugin-react` 6 transforms with `oxc-transform-react`, and Vite's config loader wants JSON imports with `with { type: "json" }`. The docs app is on **React Router 8** (the v8 future flags — `v8_middleware` — are gone; middleware is always on) and **fumadocs 16.15**, whose static search runs on its own engine (ZBSearch): `staticClient({ locale })` from `fumadocs-core/search/client/orama-static`, no Orama instance (the `@orama/orama` dependency is gone). pnpm 11 enforces a **supply-chain freshness gate** (`minimumReleaseAge: 1440` in `pnpm-workspace.yaml`) — if `pnpm install`/`pnpm <script>` fails with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`, a dependency was published <1 day ago. Wait for it to age, or allowlist that one package under `minimumReleaseAgeExclude` (never `minimum-release-age=0` globally). Dependency build scripts are also gated — approve trusted ones under `allowBuilds` (e.g. `esbuild`). When the gate blocks a `pnpm <script>` (pnpm 11 re-runs an install check first), run the tool binary directly to bypass it: `./apps/desktop/node_modules/.bin/vitest run --root apps/desktop` (vitest is package-local — not in the root `.bin`), `./node_modules/.bin/tsc --noEmit -p apps/desktop/tsconfig.json`, `./node_modules/.bin/oxlint apps/desktop/src`, `./node_modules/.bin/oxfmt --check apps/desktop/src`, `(cd apps/desktop && ./node_modules/.bin/tauri icon …)`, `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml`.
- **Keyboard-driven lists share `components/list-nav.ts`.** `subseq` is the fuzzy filter; `scrollRowIntoView(container, index)` keeps the selected row visible in the finder, command palette, theme picker, notebook switcher, and the sidebar's plain (non-virtualized) note list. It measures with `getBoundingClientRect`, **not `offsetTop`** — every one of these scroll containers is unpositioned, so `offsetTop` reports a distance from some outer scrim/panel and comparing it against `scrollTop` bakes in a constant offset (which is why scrolling back up used to never fire and scrolling down overshot). Rects put both nodes in the same space. The virtualized sidebar list uses `@tanstack/react-virtual`'s own `scrollToIndex` instead. `pointerMoved()` is the hover guard that tells real pointer motion from the synthetic hover a browser re-fires under a STATIONARY cursor (rows shifting on keyboard nav, an overlay mounting under the pointer); its baseline is the position at creation plus every hover it sees, so **whenever a picker's rows REMOUNT (leaving the palette's confirm view, the switcher's/move picker's create form) re-seed it — `moved.current = pointerMoved()` — before flipping the state**: the pointer moved while the rows were gone (the click on "No"), the remount's synthetic hover compares against a stale baseline, selects whatever row now sits under the cursor, and the next Enter runs THAT command (the pointer.spec "danger confirms" bug). Selection resets on typing live in the input's change handler, and default selections are derived at render (`sel: number | null`), never synced into state from an effect.
- **Editor styling is plain CSS now — HMR works.** The whole block-node look lives in `styles.css` (`/* ── editor: blocks ── */`, all `var()`-driven, native `::selection` on `--sel`) — no StyleModule, no specificity wars. Editor EXTENSION changes still wire at editor creation, so extension edits need a note re-open (remount) or reload to apply to a running editor.
- **New editor code must respect the WebKit selection rules** (see §editor + §vim): never `commands.focus()` during creation, never insert-a-node-and-select-into-it inside one keydown without the reassert pattern, and force-sync the DOM selection after programmatic selection dispatches on the keyboard path. Chromium forgives all three; WKWebView does not — and e2e runs BOTH engines precisely to catch this class.
